## 2. 时基

| 时钟域 | 周期 | 用途 | 来源 |
|---|---|---|---|
| `sys_clk` | 50 MHz | 全部同步逻辑 | 板载 50 MHz 晶振（T7） |
| `tick1k` | 1 ms | LQR 控制节拍、φ 除法触发、正弦相位、测速 | [bal_top.v](../src/bal_top.v) 计数器 49999 |
| `tick10` | 10 ms | 遥测帧、测速差分 | 计数器 499999 |
| `angle_valid` | ≈1.17 ms（856 Hz） | 起摆状态机帧节拍、θ 采样 | SA100 帧同步 |

> ⚠ **1 kHz 控制环 vs 856 Hz 角度帧**：θ 每 1.17 ms 才更新一次，但 LQR 每 1 ms 采样一次，
> 因此约 14% 的控制节拍复用同一帧角度。4 ms 差分本身无偏，但多了一跳量化噪声。
> 起摆状态机已经是按 `angle_valid` 跑的，LQR 没有。见 [04_已知问题.md](04_已知问题.md)。

## 3. 摆杆倾角 θ

**链路**：`SA100 PWM → 占空比解码 → 12 位位置码 → 减零点 → 绕回 → 换算 0.1°`

| 步骤 | 做法 | 出处 |
|---|---|---|
| 同步 | 两级触发器 `sync_ff` 消除亚稳态 | `bal_top.v` / `sync_ff.v` |
| 捕获 | 上升沿起计 `high_ticks`，整周期计 `period_ticks` | `pwm_capture.v` |
| 抗野值 | 高电平做 **3 点中值**（单帧 EMI 幽灵脉冲直接丢弃） | `pwm_capture.v` |
| 解码 | `position = high×4098 / period − 1`，恢复除法 32 拍 | `angle_calc.v` |
| 跳变门限 | 与上帧差（不绕回）**> 40 counts（4°）即判野值**，保持上一值；连续 100 帧被拒则强制重同步 | `angle_calc.v` |
| 零点 | `θ = position − 1330`（**标定值**，SA100 装配零点） | `bal_top.v` |
| 绕回 | `θ ≥ 2048 → θ − 4096`，得 ±2048（±180°） | `bal_top.v` |
| 定标 | `θ × 225 >> 8`（225/256 = 3600/4096） → **0.1°** | `bal_top.v` |
| 中值 | LQR 输入再过 3 点中值（`th_med`），节拍用 `angle_valid` 延迟 4 拍 | `bal_top.v` |

**为什么是 40 counts**：摆杆物理极限约 450 °/s，一帧（1.17 ms）最多走 0.53°，即约 6 counts。
40 counts ≈ 3400 °/s，留有 7 倍余量，同时能拦住「整圈野值」（4096 counts 会被绕回逻辑算成 ±196 的合法跳变）。

**量程与分辨率**：12 位 / 360° → 0.0879°/count；换算后 0.1° 分辨率，±180° 量程。

## 4. 横臂角度 φ 与角速度 φ̇

**φ**：编码器计数 → 0.1° → 对 3600 取模 → 绕回 ±1800。

| 步骤 | 做法 | 出处 |
|---|---|---|
| 计数 | 四倍频 + 5 µs 数字滤波，824.5 counts/圈 | `quad_decoder.v` |
| 定标 | `φ = pos × 4471 >> 10`（4471/1024 = 4.366 = 3600/824.5） | `bal_top.v` |
| 取模 | `udiv32` 顺序除法，**1 kHz 触发一次，32 拍完成**（刻意不用 `%`，见下） | `udiv32.v` |
| 绕回 | `> 1800 → −3600`，`< −1800 → +3600` | `bal_top.v` |

> 取模为什么用顺序除法：版本 A 里 `mult_384 → phi_mod_r` 是一条 19.964 ns 的路径，slack 只有 +0.001 ns。
> 换成 `udiv32`（1 ms 一次、32 拍）后整条路径被摘掉，代价是 φ 更新延迟 0.64 µs，可忽略。

**φ̇**：`speed_est` 在 `tick10` 上做 10 ms 差分 ×100（counts/s），再过一阶低通 `>>>2`（α=1/4，τ≈40 ms），
最后 `× 4471 >> 10` 换成 0.1°/s，限幅 ±30000。

> ⚠ 这是全链路里**唯一没有做野值/量化防护**的量，也是稳态 duty 抖振的主要来源，见第 8 节。

## 5. 摆杆角速度 θ̇

4 ms 基线差分 + 一阶低通（1 kHz 域）：

```text
h[0..4]  每 1 ms 移位一次
dth4  = (θ − h[4]) × 250       // 4 ms → 每秒；单位 0.1°/s
thd_raw = clamp(dth4, ±20000)  // ±2000 °/s
thd_lpf = thd_lpf + ((thd_raw − thd_lpf) >>> 3)   // τ = 8 ms
```

**为什么从 30 ms 改成 4 ms**：30 ms 基线的延迟让摆杆（时间常数约 88 ms）的相位裕度吃掉太多，
实测「延迟从 ~40 ms 降到 ~10 ms」后 KTH 才敢加到 4600。噪声代价用限幅 + 低通压回去
（±0.13° 的位置噪声，30 ms 差分是 6 °/s，1 ms 差分是 130 °/s —— 4 ms 是个折中）。

## 6. LQR 控制律（`lqr_core.v`，1 kHz）

### 6.1 公式

```text
dphi   = wrap(φ − φ0 − phi_tgt)      // 相对使能时刻的横臂偏差，扣掉跟随目标
dphi_dz= |dphi| < 5 (0.5°) ? 0 : dphi   // φ 环死区，压编码器量化/静摩擦抖动
th_tgt = clamp(KPH × dphi_dz / 256, ±TH_TGT_LIM)     // 外环：横臂偏差 → 倾角指令

th_err = θ − th_tgt                                   // 内环误差
prod   = KTH·th_err + KI·∫θ + KDT·θ̇ + KDP·φ̇
u_p    = −(prod >> 8)
u_c    = u_p > 0 ? u_p + 113 : (u_p < 0 ? u_p − 167 : 0)   // 死区前馈
duty   = clamp(u_c, ±2000)                                 // 80% 占空比
```

### 6.2 系数

| 参数 | 值 | 实现方式 | 物理含义 |
|---|---|---|---|
| `KTH` | 4600 | 常量乘 + 右移 8 | θ 刚度。每 0.1° 误差 → 18.0 counts |
| `KDT` | 60 | 常量乘 | θ̇ 阻尼。（很小，抗扰主要靠 KDP） |
| `KI` | 1 | 直接累加 | 积分消静差 |
| `KPH` | −30 | `(x<<1) − (x<<5)` 右移 8 | 外环增益：φ 偏 1° → θ 目标 0.117° |
| `KDP` | 130 | `(x<<7) + (x<<1)` | φ̇ 阻尼，实测甜点（75 荡、192 钝） |
| `TH_TGT_LIM` | 105（10.5°） | 钳位 | 防 dphi 绕回时 th_tgt 跳到 ±21° |
| `TH_LIMIT` | 300（30°） | 比较 | 超出即清零输出、清积分 |
| `limit` | 2000 | 输出限幅 | 80% 占空比 |
| 死区前馈 | +113 / −167 | 常数 | 补静摩擦，否则 \|θ\|<0.9° 时电机不转 |

### 6.3 几个关键设计选择（都有踩坑记录）

1. **θ 内环 + φ 外环串级**，不是「四状态并联 LQR」。
   外环只挪倾角指令、不直接出力矩。历史上曾漏删一个 `+KPH·phi10` 直接项，导致同一个 KPH 既进外环又出力矩，
   两次 φ 实验作废。
2. **积分必须门控在 `in_range` 内**。原版在下垂 θ=±1800 时也积分，1 秒累加 1.8e6，
   50 ms 就把 `integ` 顶到 ±100000，起摆把摆杆抬进 30° 的瞬间白挨一记满幅力矩。
3. **φ 误差不做 ±4° 钳位**。钳位会让位置环变成开关控制：偏差一超 4° 就是恒定 ±10.5° 指令，横臂自激转圈（0x4FFD 实测）。
4. **KDP 是移位实现**（`<<7 + <<1` = 128+2=130），避免 1 拍内乘法拖垮 Fmax。

### 6.4 饱和特性

`duty = (4600·|θ| + 113) >> 8`，打满 2000 需要 |θ| ≈ **105 counts = 10.5°**。
超过 10.5° 后控制器进入 bang-bang，D 项（1.1 的 KDT=120，500°/s 时才 234 counts；1.0 为 60/117）在 2000 面前等于零。

> 📌 早期的抗扰日志写的是「5.6° 打满」，与代码算出的 10.5° 差整 2 倍，见 [04_已知问题.md](04_已知问题.md) 第 6 条。

## 7. 起摆状态机（`swing_ctrl.v`，帧节拍 = 856 Hz）

能量泵方案：以「摆轴能量误差 × 摆速方向」注入力矩，每摆一周注一次能量。

```text
E = cosθ − 1                      // 归一化到竖直=0；θ 单位由 L_MM 折算
u ∝ KP_PUMP × (E_target − E) × sign(θ̇·cosθ)      // PUMP_PROP=1
```

| 状态 | 语义 | 主要动作 |
|---|---|---|
| 0 `S_IDLE` | 待机 | 等 `run_en` |
| 1 `S_KICK1` | 正向 kick | 1300 mA / 250 ms，先把摆「推起来」 |
| 2 `S_KICK2` | 反向 kick | 反向 1300 mA / 250 ms，制造初始摆幅 |
| 3 `S_PUMP` | 泵能 | 按上式，`I_FLOOR` 从 700 mA 每 2.5 s 加 100 mA 到 1500 mA |
| 4 `S_WAIT` | 滑行 | 150 ms 最短驻留，防 3/4 态快速抖动 |
| 5 `S_BAL` | 已捕获 | 把电机交给 LQR (`lqr_on`) |
| 6 `S_FALL` | 掉摆 | 重新进 0 |

**捕获判据**：`|θ| < ANG_CAP(25°)` 且 `|θ̇| < W_CAP(15°/s)` 连续 2 帧 → 进 `S_BAL`。
**掉摆判据**：`|θ| > 29°` 连续 2 帧 → `force_fall` → 回状态机重摆（LQR 自身的硬门限是 30°）。

**交接握手**：`lqr_on = run && (sw_state == 5) && !lost_hard`。
刻意不用早期那个「|θ|<15° 就永久锁存」的方案 —— 起摆还没把摆送到位就把电机抢走，结果必然倒。

**在线 A/B**：串口发 `i` 翻转 `sw_inv_r`（泵能方向），不用重烧。

## 8. 稳态执行器抖振（实测特性，不是 bug）

平衡稳态下 duty 并不是一条平滑曲线：

| 指标 | 1.0（514.8 s 段） | **1.1 定版（660.1 s 段）** |
|---|---|---|
| 符号翻转率 | 10.1 次/秒 | **≈16 次/秒**（频率翻倍、幅值腰斩） |
| 主频 | 5.1 Hz | **8.0 Hz**（FFT 8.03） |
| 峰峰值 | 3620 counts（≈ ±1810） | **2322 counts（≈ ±1161）** |
| 同期 θ 波动 | \|θ\| p95 3.50°，p50 1.70° | **\|θ\| p95 1.60°，p50 0.70°** |

**为什么 1.1 更"抖"却更准**：θ̇ 低通由 8 ms 收到 2 ms 后，D 项不再把摆杆的快速运动滤掉，
反而把编码器量化噪声更多地带进 `dθ/dt`，于是执行器换向更快、幅值更小 —— 摆杆反而稳了（p95 1.60°）。

**量化推算（推断，未单独实测）**：`φ̇` 由 10 ms 差分的 1 个计数误差产生
`1 count/10 ms = 100 counts/s → ×4.366 = 437 (0.1°/s) → KDP 项 = 130×437/256 ≈ 222 counts`。
1.1 观测到的峰峰 2322 相当于每次采样有约 ±5 counts 的差分噪声（1.0 为 ±8），
与"KDP 抬高了抖振频率、低通宽度决定幅值"的预期一致。

**执行器一直在 ±1200 counts 之间来回推，而摆杆几乎不动** —— 这是位置环 + 静摩擦 + KDP 放大量化噪声形成的极限环。

它对功能不致命（θ 稳得住、duty 不饱和），但会带来三个后果：
1. 电机持续换向、发热、有噪音；
2. duty 频谱里有 5~12 Hz 能量，抬 KDT/KDP 容易撞上机械共振（历史 11.4 Hz 自激就是这条路；1.1 的主频 8.0 Hz 已经离 11.4 Hz 不远，这是**不能继续抬 KDT 的硬理由**）；
3. 横臂靠这个随机抖振缓慢游走，是"0.83 °/min 慢漂"的一个候选原因。

改进方向见 [04_已知问题.md](04_已知问题.md)。

## 9. 跟随（位置控制，拓展要求①②）

**目标**：在不倒的前提下让横臂转到指定位置。

| 项 | 值 / 做法 |
|---|---|
| 进入 | 轨迹页选中（`traj_sel=0`）→ `follow_en` 有效 |
| 进入瞬间 | 目标 = **当前横臂位置**，横臂不动（零位移进入） |
| 每格 | 旋钮一格 ±18°（`FOLLOW_STEP=180`） |
| 参考轨迹 | 目标以 1/2/3/4 counts 每 3 ms 推进，由速度页选档（屏显 30/60/90/120 °/s；`follow_slew` 注释写 10/20/50/100，与屏显不符，见 [04](04_已知问题.md) D-6） |
| 保护 | `\|θ\| > 8°` 冻结参考推进；目标只在 `lqr_on` 时有效 |
| 退出 | 目标停在最后值，横臂原地静止 |

**定版实测（`v30_S7b.csv`，30 s）**：目标 +18° → 实测 **+14.4°**，静差 **−3.6°**，
过程过冲 26°（59 counts）后回落并稳住；摆杆 \|θ\| p50 0.70° / p95 1.60°（与纯平衡相同）、
duty **0 帧饱和**。→ **单格阶跃已通过**，目标一次跳很大/连续多格仍会掉摆（见 04 的 A-1）。

**位置环怎么起作用**：目标不是直接给电机，而是变成 `phi_tgt` 送进 `lqr_core`，
从 φ 误差里减掉 —— 横臂落后目标 → dphi 有偏差 → 外环给出倾角指令 → 摆杆倾 → 横臂被"拽"过去。
所以**位置控制是借摆杆的重力/惯性完成的**，摆杆必须一直倾斜，这就是拓展要求③（全程直立）天然困难的原因。

## 10. 正弦轨迹（拓展要求②）

| 项 | 值 |
|---|---|
| 波形 | 256 点正弦表 + 线性插值，1 kHz 相位累加（`sin_gen.v`） |
| 幅度档 | 20° / 35° / 50°（`traj_sel` = 1/2/3） |
| 频率档 | 0.153 / 0.244 / 0.351 / 0.503 Hz（相位步长 10/16/23/33） |
| 基准 | **进入正弦时记下当前横臂位置**（`sin_base`），正弦叠加在该基准上（11.0 的修正） |

> 11.0 之前 `phi_tgt = sin_y` 是绝对零基准，切进正弦时目标会**先跳回 0** 再摆 —— 这是 11.0 的主要改动。

## 11. 安全与保护

| 保护 | 判据 | 动作 |
|---|---|---|
| 摆角超限 | \|θ\| > 30° | LQR 输出清零 + 积分清零 |
| 掉摆 | \|θ\| > 29° 连续 2 帧 | 交给起摆状态机重摆 |
| 传感器丢帧 | 5 ms 无帧 → `sensor_lost`；持续 ≥50 ms → `lost_hard` | 短丢帧继续用上一角度撑住；≥50 ms 才真断 |
| 过流 | ADC > 1800（≈1.47 A）连续 5 ms | `fault` 锁存，电机 EN 拉低，数码管显示 `8`；换模式或复位清除 |
| 上电 | — | 起摆需 `run` 才使能；电机默认不转 |

> 50 ms 丢帧容忍是实测加出来的：起摆捕获瞬间 SA100 偶发丢帧，原来 `lqr_on` 立刻断开、duty 清零，
> 摆杆 0.24 s 内从 +3° 滑到 −69° 掉摆（"到顶了却不接住"）。

## 12. 遥测帧（VOFA JustFloat，6 通道 @100 Hz）

```text
每帧 28 字节：float32 ch0..ch5（小端） + 00 00 80 7F
```

| 通道 | 内容 | 说明 |
|---|---|---|
| ch0 | `{8'd0, sensor_lost, sw_state[2:0], mode[3:0]}` | 解码：`state = (ch0>>4) & 7`；`lost = (ch0>>7)&1` |
| ch1 | `duty` | counts，±2000 |
| ch2 | `pos_r[15:0]` | 横臂相对计数 |
| ch3 | `θ` | 0.1° |
| ch4 | `adc_data` | MCP3201 原始码 |
| ch5 | `{sw_inv_r, sw_e_dbg[14:0]}` | 起摆能量诊断 |

**缺口**：没有 `phi_tgt` / `phi_ref`，也没有 `rej_cnt`（野值拒绝计数）。
所以「跟随掉摆的机理」和「野值率」这两件事目前**没法从数据上验证**，只能靠推断。
扩到 8 通道是二十行的事（`LEN 28→36`、`csel` 加一位，带宽 2.8→3.6 kB/s，115200 下 31%）。
