# 03 · 数据文件与复算方法

> 本文定义每个 CSV 的字段、每个判据的口径、以及怎么一条命令把报告里的数字重算一遍。
> **报告里出现的任何实测数字，都应该能在这里找到出处。**

---

## 1. 数据来源与链路

```text
FPGA 100 Hz 遥测（VOFA JustFloat，6 通道，115200）
   → tools/capture_raw.ps1（PowerShell 串口抓包，逐帧落盘）
   → docs/data/*.csv
   → tools/recompute_all.py（复算）/ tools/plot_measured.py（出图）
```

抓包脚本按 JustFloat 帧尾 `00 00 80 7F` 分帧，每帧 28 字节取 6 个 float32。

## 3. 字段定义

| 列 | 含义 | 单位 | 换算 |
|---|---|---|---|
| `t` | **帧序号**（不是毫秒） | 帧 | 秒 = `t / 100` |
| `theta` | 摆杆倾角 θ | 0.1° | ° = `theta / 10` |
| `duty` | 电机占空比 | counts | 2500 = 100%；限幅 ±2000 |
| `state` | 起摆状态机 `sw_state` | — | 0 停 / 1 kick / 2 反踢 / 3 泵能 / 4 滑行 / 5 平衡 / 6 掉摆 |
| `pos` | 横臂编码器相对计数 | counts | 824.5 counts/圈 → ° = `pos × 0.4366` |
| `ch0` | 原始 ch0 打包值 | — | `state = (ch0>>4)&7`，`sensor_lost = (ch0>>7)&1` |
| `ch5` | 原始 ch5 打包值 | — | `{sw_inv_r, e_dbg[14:0]}`，起摆能量诊断 |

> ⚠ `t` 是**帧序号**不是毫秒。`capture_raw.ps1` 里 `$n` 自增后直接写进第一列，
> 按 100 Hz 换算成秒要 `÷100`。别直接当 ms 用（会差 10 倍）。

## 4. 判据口径（统一）

| 量 | 定义 |
|---|---|
| **起摆成功** | 进入 `state=5` 后连续保持 ≥ **2 s**（不是"碰到 state5 就算"） |
| **捕获时间** | `state` 由 1 变为 5 的时间差 |
| **连续平衡段** | `state=5` 的最长连续帧数 ÷ 100 |
| **稳态段** | 最长平衡段**去掉前 5 s**（捕获瞬态） |
| **θ 统计** | 在稳态段上算 p50 / p95 / rms / max，取绝对值 |
| **duty 饱和** | `\|duty\| >= 2000` 的帧 |
| **横臂漂移** | 段内 `pos` 末值 − 首值（净漂）与 `max − min`（峰峰） |
| **一次推扰** | 1.0 口径：`state=5` 内 `\|θ\| >= 8°` 的超阈事件，间隔 < 0.3 s 的合并为一次；<br>1.1 口径（v30_S6）：`\|θ\| >= 4.5°` 起判、**2 s 内合并**——阈值更低是为了不漏掉轻推，合并窗更长是因为 8 Hz 抖动会反复越阈 |
| **回正时间** | 峰值那一帧起，到 `\|θ\|` 连续 0.5 s 都在 2.5° 以内为止 |
| **跟踪率** | 实测幅度 ÷ 设定幅度（正弦段取 θ 的 5%~95% 分位之差的一半） |

## 5. 复算

### 5.1 定版 campaign（1.1，v30_S*.csv）

```powershell
# 单段复算（以 S4 长跑为例；脚本读 docs\data\<file>.csv，列 t,ch0,duty,pos,theta,adc,ch5）
python tools\recompute_v30.py S4
```

当前基线输出（与 `python tools\recompute_v30.py S4` 的实际打印逐字一致）：

```text
【S4】66007 帧 / 660.06 s / 100.0 Hz
  sensor_lost 帧           : 0
  state 分布               : {5: 66007}
  最长 state=5 段          : 66007 帧 = 660.1 s（起点 0.00 s）
  |θ| p50 / p95 / rms      : 0.70° / 1.60° / 0.86°
  |θ| max / θ 范围         : 2.40° / -1.80° ~ 2.40°
  duty mean|.| / 峰值       : 421 / 1161（限幅 ±2000）
  duty 饱和帧数             : 0
  横臂净漂 / 峰峰           : -21 counts (-9.2°) / 33 counts
  横臂漂移速率              : 0.83 °/min
  抖动主频（过零估）        : 7.97 Hz
```

> 主频：脚本用"θ 去均值后的过零率"估，S4 得 7.97 Hz；对同一段做 FFT 得 **8.03 Hz**，
> 两者差 <1%。报告统一写 FFT 值，脚本输出有 ±0.1 Hz 的口径差异属正常。
> rms 按**带符号 θ 对 0** 计算（`sqrt(mean(θ²))`），不是对 `|θ|` 的均值算。

## 7. 抓包（补测时用）

```powershell
cd <仓库根目录>\tools\experiments_20261102
.\capture6.ps1 -Port COM8 -Seconds 60 -Out "..\..\docs\data\v30_Sx.csv"
```

> **端口是 COM8**（不是旧文档里的 COM6）。
> `capture6.ps1` 是 2026-11-03 重写过的版本：按 JustFloat 帧尾 `00 00 80 7F` 分帧后，
> 会对 6 个 float 做范围校验（ch0∈[0,4095]、|duty|≤2600、|pos|≤2e6、|θ|≤4000、
> adc∈[−10,6000]、|ch5|≤40000），越界判为**假帧尾**、跳 1 字节重新同步。
>
> 旧脚本 `capture_raw.ps1` 不做校验，帧尾恰好出现在浮点数据时会解出 `-1.38E+19` 之类的假帧，
> 导致 `[int]` 溢出报错、约 0.9% 帧丢失（S2 就丢了一部分）。补测请一律用 `capture6.ps1`。
