## A. 影响赛题得分的

### A-1　跟随大目标阶跃仍会掉摆（拓展要求③只做了一半）　`开放`

**现象**
跟随过程中横臂持续朝一个方向转，摆杆缓慢发散直至掉摆。实测一例：
t=21.85 s 掉摆，当时**野值计数为 0**，θ 单调发散 −32° → −43.8° → −60.7° → −66.4°，
duty 全程 ±2000 饱和，而横臂 pos 几乎不动。

**2026-11-03 晚的定版实测（`v30_S7b.csv`）**
单格目标（+18°）能站住：实测 +14.4°、静差 −3.6°、过冲 26° 后回落，摆杆 p95 1.60°（与纯平衡同），
duty 0 帧饱和。**结论：小阶跃没问题，问题只出在"目标一次跳很大 / 连续多格"这一侧**，
与本条推断的"目标跑在实际位置前面太远"一致，但仍未用 `phi_tgt` 通道直接证明。

**现有解释（推断，未经验证）**
跟随目标推进跑在实际位置前面太远 → `th_tgt`（外环倾角指令）被顶到 ±10.5° 饱和 →
摆杆被要求一直倾 10.5° → KTH 拉不回来。

> ⚠ **这条是推断，不是实测。** 遥测里没有 `phi_tgt` / `phi_ref` 通道，
> 无法直接证明"目标跑在前面"这个前提。见 C-1。

**已试过并否决的方案**（别再重复）

| 方案 | 结果 | 原因 |
|---|---|---|
| `lqr_core` 里把 φ 误差夹到 ±4° | 横臂自激转圈（0x4FFD） | 位置环变成开关控制 |
| 目标超出实际 5° 就冻结 | 无明显效果（0x48BC，已回滚） | 冻结不改变已有误差 |
| 停转 500 ms 后目标吸附实际位置 | 手感很差（0xE764，已回滚） | 停手瞬间目标跳变 |

**已修的一处**：`lqr_core.v:114-118` 原本 `th_tgt = KPH*dphi/256` 无限幅，dphi 绕回 ±1800 时
`th_tgt` 会跳到 ∓211（21.1°）直接把 duty 打满；11-02 已钳到 `±TH_TGT_LIM`（默认 5°）。
这是"平衡中突然倒"的候选根因，定版后未再复现。

**建议（按性价比）**
1. 先扩遥测加 `phi_tgt`/`phi_ref`（半天）—— 否则后面全是盲调；
2. 给 `lqr_core` 加 `th_tgt_lim` 输入端口，跟随时传 35（3.5°）、平常传 105 —— **只降饱和天花板，不改线性区**，不会像第一条那样自激（README 里提过，未实现）；
3. 修 A-4 的软着陆 bug（1 小时，见下）；
4. 若时间不够：如实写进报告"位置控制存在特定工况失稳，机理已定位、方案已提出"。

### A-2　时序余量只有 9 ps（1.0 时为 3 ps）　`开放`

**证据**：`evidence/timing_report.tr` / `impl/pnr/LQR_end.timing_paths` ——
1.1 定版 Fmax **50.022 MHz**（约束 50.000），TNS 0，最差 setup 路径 slack **+0.009 ns**
（data delay 24.316 / 24.325 ns），端点 `u_menu/r_anim_0_s0/Q → u_menu/frm_frm_4_1_s0/DI[3]`；
1.0 的同一条路径是 +0.003 ns / 50.008 MHz。

**根因**
OLED 帧缓冲 `frm[0:1023]` 用了**同址读改写**：

```verilog
frm[{small_page, small_sum[6:0]}] <= frm[{small_page, small_sum[6:0]}] | small_data;
```

BSRAM 做不了"同一拍读了再写回同一地址"，综合器只能退化成 **648 个 SSRAM（分布式 LUT RAM）**，
于是这一拍里要串完：
`r_anim → small_cx → small_sum → small_addr → 图标 ROM 读（异步 LUTRAM）→ OR → 写口`。

**影响**：功能**不受影响**（时序是过的）。但任何改动 OLED 相关逻辑都可能把 slack 打成负的。

**建议**
- 最小改动：把 `fb_wdata` 打一拍，或把同址读改写拆成"读 → 或 → 写"两拍；
- 根治：换成分页合成（一次合成一行/一页缓存），或加 BSRAM 约束（1024×8 只占 1 块 16 Kb BSRAM）；
- **提交前不要动**（见 A-3 的理由）。

### A-3　三套 OLED 驱动并行，UI 吃掉一半逻辑　`设计如此，但代价高`

| 模块 | LUT（含子模块） | 内含 |
|---|---|---|
| `u_menu` | 1758 | 一份 `sh1106_i2c` + 一份 128 LUT 帧缓冲 |
| `u_oled` | 1467 | 第三份驱动（含 119 LUT 分频 + 241 LUT 渲染） |
| `u_speed` | 669 | 第二份驱动 + 帧缓冲 |

三件套合计约 **3957 LUT ≈ 全设计 51%**；控制部分（起摆 + LQR + 角度 + 测速）约 **1500 LUT ≈ 19%**。
而 `oled_scl/oled_sda` 最后只是三选一复用同一组引脚（`bal_top.v` 末尾的 `assign`），
同一时刻只有一路可见。

**影响**：CLS 已到 **73%**，是资源瓶颈；也是 A-2 那条关键路径的来源。

**建议**：合并成一个 I2C 驱动 + 一套帧缓冲 + 页路由，可省 20~25% 逻辑，并很可能顺带消掉关键路径。
**工作量 2~3 天，提交前不要做。**

## B. 代码里能直接改的

### B-1　跟随"软着陆"的方向写反了　`开放`（建议修）

**位置**：`src/bal_top.v` 第 800~804 行

```verilog
wire [16:0] err_abs  = err_w[16] ? ((~err_w) + 17'sd1) : {1'b0, err_w[15:0]};
wire [16:0] slew_abs = (err_abs < 17'sd30) ? (err_abs >>> 1) : {13'd0, step_n};
wire [16:0] step_abs = (slew_abs > err_abs) ? err_abs : slew_abs;
```

**问题**：正常爬升上限是 `step_n` = 1~4 counts / 3 ms（33~133 °/s）。
但误差小于 3°（30 counts）时走 `err/2` 分支：`err=29` 时单步 **14 counts ≈ 467 °/s**，
是额定值的 **3.5 倍**，且在 `err=30` 处是 4→14 的**跳变**。

**后果**：每转一格，参考轨迹在到位前 3° 突然加速，正好在最不该扰动摆杆的时刻踢一脚。
大概率是"跟随阶跃约 50% 过冲"的贡献项之一。

**补丁**（4 行，不触碰状态机）：

```verilog
wire [16:0] err_abs   = err_w[16] ? ((~err_w) + 17'sd1) : {1'b0, err_w[15:0]};
wire [16:0] half_abs  = err_abs >>> 1;
wire [16:0] slew_cap  = {13'd0, step_n};
wire [16:0] slew_abs  = (half_abs < slew_cap) ? half_abs : slew_cap;   // min(err/2, step_n)
wire [16:0] step_abs  = (slew_abs > err_abs) ? err_abs : slew_abs;
```

**注意**：改动后必须走完「综合 → 烧录 → 起摆 3 次 + 跟随 3 格」的验证；
如果验证条件不具备，**宁可保留已知的小 bug，也不要烧未验证的码流**。

### B-2　积分作用在绝对 θ 上，不是跟踪误差　`开放`（结构性问题）

**位置**：`src/lqr_core.v` 第 241 行

```verilog
else integ <= integ + theta10;      // 而不是 theta10 − th_tgt
```

**问题**：纯平衡时 `th_tgt≈0`，两者等价；一旦跟随让 `th_tgt` 变成 ±10.5°，
积分会慢慢累积出反向力矩去把 θ 拉回 0，**抵消倾斜指令**。`I_LIM` 允许它攒到 ±390 counts
（约 20% 的 duty 上限）。

**后果**：跟随长时间单向转时，横臂会落后于目标 —— 与 02 文档里"跟随精度是开环的、长时间累积偏差"
是同一件事的两个面。

**建议**：改成 `integ <= integ + (theta10 - th_tgt)`。但会改变平衡特性，**必须重新上板验证**。

### B-3　`lqr_core` 里 φ 的低通实际没有滤波效果　`待复核`

**位置**：`src/lqr_core.v` 第 84~87 行

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) phi_lpf <= 0;
    else        phi_lpf <= phi_lpf + ((phi10 - phi_lpf) >>> 3);
end
```

**问题**：这段写在 **50 MHz 时钟域**（每个时钟都更新），`>>>3` 对应 τ = 8 × 20 ns = **0.16 µs**，
因此它只是把 φ 的阶梯边缘磨圆 8 个时钟，**不是一个 8 ms 低通**。
但上一行注释写的是"τ≈8 ms"。

**影响**：无害（φ 本来就是 1 ms 更新一次的阶梯），但注释与实现不符，
答辩被问"你的 φ 滤波时间常数是多少"时会答错。

**建议**：要么把注释改成实际值，要么把它挪进 `tick1k` 分支做成真的 8 ms 滤波（需重新验证）。

### B-4　1 kHz 控制环 vs 856 Hz 角度帧　`设计如此`

θ 每 1.17 ms 更新一帧，LQR 每 1 ms 采样一次，约 **14% 的控制节拍复用同一帧**。
4 ms 差分本身是无偏的（测量的是真实 4 ms 位移），但会多一跳量化噪声。

**建议**：把 LQR 也挂到 `angle_valid`（856 Hz）上跑 —— 起摆状态机已经是这么做的。
改起来不大，但会改变控制频率，**要重新验证**。

### C-2　离线仿真脚本跑不起来　`开放`

```text
python sim/furuta_closed_loop.py
TypeError: not all arguments converted during string formatting   (第 728 行)
```

`log` 元组有 12 个字段，格式串只有 9 个占位符。
另外 `log` 只在 `verbose=True` 时才填，而所有统计量都从 `log` 算 ——
所以 `--swp` 模式下 **`p95|θ|` 永远是 `nan`**，扫描表的质量列是空的。

**影响**：`sim/` 名义上是"回归工具"，实际目前不可用。
`sim/README.md` 里"用它做回归"的说法**不成立**，写报告时别引用。

**修法**：补 3 个 `%` 占位符 + 让 `log` 在 `verbose=False` 时也填（约半小时）。
但注意：模型用的增益是设计增益，**模型里这组固件增益是临界的**，不会稳定 —— 模型的用途只有"验方向/验状态机"。

## D. 口径与记录问题（写报告前必须处理）

### D-1　"5.6° 饱和"与代码算出来的 10.5° 差一倍　`待复核`

`tools/experiments_20261102/ANTI_DISTURBANCE_LOG.md` 第 45 行写：

> `KTH=4600` 让 duty 在 |θ|≈5.6° 就打满 ±2000

按当前 RTL 重算：`|duty| = (4600·|θ|₀.₁° + 113) >> 8`，打满 2000 需要 `|θ| ≈ 105 counts ≈ 10.5°`。
差了整 2 倍。

**两种可能**
1. 当时那次实验的口径不同（例如把 `±1000` 当满量程），日志记错了 → 需要重算饱和点；
2. 5.6° 是实测值，那么它一定包含了 `KDP·φ̇` 或 `θ̇` 项的贡献 → 结论要改写成"多状态耦合下的饱和"

**影响**：这份日志推出了"KTH 3600 + KDT 120（饱和点 7.2°）"的整改方向。
如果饱和点本来是 10.5°，那个重调方案的前提就变了。

**建议**：用 `tools/dist_logs/*.csv` 重新标一次饱和点再谈增益重调。
在复核完成前，**报告里不要引用"5.6°"这个数**。

### D-3　`UserCode` 不是版本号　`认知纠正`

码流头里：

```text
//CheckSum: 0x6A6F
//UserCode: 0x00006A6F
```

`UserCode` 等于 `CheckSum`，是综合器算的配置校验和，**不是设计出来的版本标识**。
它仍然可以作为"这一版码流的唯一指纹"用（内容变则校验和变），
但不能理解成"我给 6.0 编了个 0x7D58 的版本号"。
