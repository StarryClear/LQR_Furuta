# 改名重建复验记录

> 目的：证明 `LQR_end` 只是 `LQR_11.0` 的**改名副本**，RTL 与综合结果完全等价。
> 复验时间：2026-11-03　|　工具链：Gowin V1.9.12.04 (64-bit)，gw_sh 命令行

---

## 1. 改了什么

| 项 | 原名 | 新名 |
|---|---|---|
| 工程文件 | `LQR_11_0.gprj` | `LQR_end.gprj` |
| 用户设置 | `LQR_11_0.gprj.user` | `LQR_end.gprj.user` |
| 物理约束 | `src/LQR_11_0.cst` | `src/LQR_end.cst` |
| 时序约束 | `src/LQR_11_0.sdc` | `src/LQR_end.sdc` |
| 构建脚本 | `open_project LQR_11_0.gprj` | `open_project LQR_end.gprj` |
| 输出基名 | `LQR_11_0` | `LQR_end`（由工程名派生） |

**没有改的**：`src/*.v` 全部 36 个 Verilog 文件**一个字节都没动**；模块名、参数、引脚全部保持原样。

## 3. 码流逐字节比对

两个 `.fs` 都是 7,264,153 字节，逐字节比较：

```text
diff bytes: 4
first: 543   last: 549
  @543  A='//Created Time: Tue Nov  3 13:54:24 2026'
  @549  B='//Created Time: Tue Nov  3 11:30:21 2026'
payload after byte 2048 identical: True
```

**结论：除文件头里的构建时间戳（4 个字节）外，两个码流逐字节完全一致。**

（SHA256 不同是因为那 4 个字节；配置数据本身相同，这与 `CheckSum: 0x6A6F` 相等互为印证。）

## 4. 复现方法

```powershell
cd <仓库根目录>
& "$env:GOWIN_HOME\IDE\bin\gw_sh.exe" build.tcl
# 检查 impl\pnr\LQR_end.fs 头部：//CheckSum 应为 0x6A6F
```

⚠ `build.tcl` 必须是 **UTF-8 无 BOM**。本次改名时第一次构建就踩了这个坑，
`gw_sh` 报 `invalid command name "??pen_project"` —— 见 [../docs/05_编码约定.md](../docs/05_编码约定.md)。
